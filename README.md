# VPN Watcher

Telegram-бот для существующих клиентов 3x-ui **3.11.0**. Пользователь вводит Email из панели, администратор подтверждает привязку. Бот напоминает об окончании подписки и продлевает доступ на 30 дней после ручной проверки оплаты.

Пошаговая инструкция для установки и обновлений из GitHub — [развёртывание на Ubuntu](DEPLOYMENT.md).

## Запуск через Docker Compose

1. Создайте отдельного бота в BotFather. Один токен должен обслуживаться одним экземпляром приложения. Для встроенного бота 3x-ui используйте отдельный токен.
2. В настройках 3x-ui создайте API-токен, позволяющий читать и изменять клиентов. В версии 3.11.0 для этих операций подходит токен со scope `admin`. Токен даёт административный доступ к панели.
3. Из каталога проекта выполните `Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Linux. Впишите значения из таблицы. Образ получает их при запуске.
4. Выполните `docker compose up -d --build`. Статус проверяется командой `docker compose ps`, журнал — `docker compose logs --tail 100 bot`.
5. Первым откройте личный чат с ботом и нажмите **Старт**, чтобы он мог присылать вам заявки. Пользователь также начинает работу командой `/start`.

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен отдельного Telegram-бота |
| `ADMIN_ID` | Ваш числовой Telegram ID. Для уже работающего бота команда `/id` показывает ID отправителя |
| `PANEL_URL` | Доступный **из контейнера** адрес панели, включая пользовательский базовый путь, например `https://vpn.example.org/private-path`. Приложение добавляет `/panel/api/clients/` самостоятельно |
| `PANEL_TOKEN` | Выданный панелью Bearer-токен |
| `REMINDER_DAYS` | За сколько дней напомнить. По умолчанию 3 |
| `TIME_ZONE` | Зона для отображения времени. По умолчанию `Europe/Moscow` |

Используйте HTTPS с доверенным сертификатом для удалённой панели. В контейнере адрес `localhost` указывает на сам контейнер. Бот получает обновления из Telegram через long polling. Compose сохраняет SQLite в томе `watcher-data` и запускает сервис после перезапуска Docker. При обновлении конфигурации выполните `docker compose up -d --build`. [API 3x-ui 3.11.0](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/docs/content/docs/en/reference/api/index.mdx)

## Автозапуск после перезагрузки Linux

В `compose.yaml` у сервиса `bot` уже указано `restart: unless-stopped`. Когда сервер загружается, systemd запускает Docker, а Docker поднимает контейнер бота, если он работал до перезагрузки. [Политики перезапуска Docker](https://docs.docker.com/engine/containers/start-containers-automatically/)

На сервере с systemd и системной установкой Docker Engine один раз включите автозапуск Docker. После заполнения `.env` запустите контейнер из каталога проекта. [Автозапуск Docker в Linux](https://docs.docker.com/engine/install/linux-postinstall/#configure-docker-to-start-on-boot-with-systemd)

```sh
sudo systemctl enable --now docker.service containerd.service
sudo docker compose up -d --build bot
```

Проверьте настройки командами `systemctl is-enabled docker.service` и `sudo docker compose ps bot`. Первая должна вывести `enabled`, вторая — показать работающий контейнер. После следующей штатной перезагрузки состояние можно проверить той же командой `ps`.

Ручная остановка через `docker compose stop bot` сохраняется и после перезагрузки. Чтобы вернуть бота в работу, выполните `sudo docker compose up -d bot`.

## Как обрабатываются заявки

- **Регистрация.** Клиент нажимает «Регистрация» и вводит Email или имя из панели. Вы видите идентификатор, Telegram ID и имя пользователя. Сверьте личность и выберите «Подтвердить привязку», «Запросить исправление» или «Отклонить». Если у клиента уже есть другой Telegram ID, бот покажет оба ID и отдельно запросит подтверждение замены.
- **Подписки.** «Моя подписка» открывает карточку с актуальным сроком и кнопкой «Я оплатил». Если подписок несколько, кнопки под карточкой позволяют их перелистывать. При запуске с пустым списком привязок бот сам находит в 3x-ui всех клиентов с личным Telegram ID и включает их в проверку напоминаний.
- **Напоминания.** Раз в час бот проверяет известных владельцев. Для каждой даты окончания формируется одно напоминание. Перед отправкой бот ещё раз проверяет срок и владельца. Если встроенный бот панели тоже рассылает предупреждения, настройте нужный источник уведомлений.
- **Продление.** После «Я оплатил» проверьте поступление денег и нажмите «Продлить на 30 дней». Для активной подписки срок отсчитывается от текущего окончания, для истёкшей — от момента подтверждения. Клиент получает сообщение после сверки записи в панели. Кнопка сообщает о совершённой оплате. Продажа цифровой услуги внутри Telegram регулируется правилами Telegram Stars. [Правила Telegram](https://core.telegram.org/bots/payments-stars)
- **Истёкшая и выключенная запись.** Панель 3.11.0 может сама выключить клиента по истечении срока. Доступ, выключенный администратором, может выглядеть так же. Бот показывает это в карточке. Кнопка «Включить и продлить на 30 дней» разрешает оба действия. При обычном продлении бот сохраняет флаг доступа. Для бессрочного или ещё не активированного срока, исчерпанной квоты, настроенного автопродления и действующей заблокированной подписки проверьте карточку в панели.
- **Очередь администратора.** В меню «Ожидают решения» есть фильтры регистраций и продлений. После решения бот обновляет карточку заявки. Если администратор оформил заявку для себя, он видит результат в этой же карточке. Изменившиеся владелец или срок требуют проверки новой карточки. Заявку, по которой панель явно отклонила запись, можно сверить в панели и обработать повторно с той же целевой датой.

## Частота и очереди

| Настройка | По умолчанию |
|---|---|
| `USER_ACTIONS_PER_MINUTE` | 12 действий в минуту на пользователя, начальный запас до 6 |
| `PUBLIC_ACTIONS_PER_MINUTE` | 60 действий в минуту для всех обычных пользователей, начальный запас до 12 |
| `MAX_OPEN_REGISTRATIONS` | 50 незакрытых регистраций, максимум одна на пользователя |
| `MAX_OPEN_RENEWALS` | 100 незакрытых заявок о платеже |
| `MAX_USER_RENEWALS` | 3 незакрытые заявки о платеже от одного пользователя для разных подписок |

Запас действий восстанавливается постепенно. Одновременно обрабатываются до трёх пользовательских действий и до одного на пользователя. При превышении лимита частые события пропускаются до обращения к панели. Повторите действие через несколько секунд. Администратор имеет отдельный допуск к обработке.

При заполнении очереди бот отвечает, что новая заявка не создана. Заявки, ожидающие решения, записи или ручной сверки, занимают место до завершения. Повторная подача той же заявки возвращает её номер. Очереди сохраняются в SQLite. Счётчики входной частоты хранятся в памяти одного процесса.

## Данные и восстановление

Если SQLite бота потеряна, запустите его с прежним токеном и доступом к той же панели. До первой проверки напоминаний бот считывает список клиентов 3x-ui и сохраняет у себя ID записи, Email и Telegram ID. Ранее зарегистрированным пользователям ничего нажимать не нужно. Если панель недоступна, бот повторяет попытку примерно через минуту. При обычном перезапуске с уже сохранёнными привязками полная загрузка пропускается.

История заявок и отправленных уведомлений восстанавливается из резервной копии SQLite. После её потери клиент в периоде предупреждения может получить то же напоминание ещё раз.

3x-ui хранит текущего владельца и срок. SQLite хранит заявки, исходную и целевую даты, решения администратора, известные привязки и очередь уведомлений. Если соединение пропало после записи, бот перечитает клиентскую карточку и сверит с уже сохранённой целью. Если Telegram подтвердил отправку, а процесс остановился до сохранения этого факта, уведомление может прийти повторно. Повторное сообщение само по себе подписку не продлевает.

Для резервной копии выполните команды из каталога проекта. Подставляйте новое имя файла для каждой копии. Команда использует SQLite Backup API и проверяет целостность результата.

```sh
docker compose exec bot python -m watcher --backup /tmp/watcher-backup-01.sqlite3
docker compose cp bot:/tmp/watcher-backup-01.sqlite3 ./watcher-backup-01.sqlite3
```

Для восстановления остановите старый экземпляр. Используйте новый том и скопируйте в него проверенную резервную копию под именем `/app/data/watcher.sqlite3` с правами на чтение и запись для UID 10001. Исходный том сохраните до сверки. После восстановления старой копии проверьте открытые заявки в 3x-ui до запуска бота. У панели есть собственная база и собственные резервные копии.

## Проверки

С Python 3.11 в виртуальном окружении из каталога проекта выполните:

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Автотесты проверяют сценарии Telegram через локальный транспорт, права, замену владельца, исключения по сроку, сохранение цели при потере ответа, восстановление после перезапуска, резервную копию и ограничения нагрузки. На отдельном экземпляре 3x-ui 3.11.0 с VLESS также проверены потеря доступа при истечении срока и восстановление подключения по прежней конфигурации после подтверждения.

Остаточные риски и область проверки описаны в [отчёте об устойчивости к перегрузке](SECURITY-REVIEW.md).
