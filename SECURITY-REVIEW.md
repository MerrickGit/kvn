# Устойчивость VPN Watcher к перегрузке

Проверка от 26 ноября 2026 года охватывает Telegram-обработчики, обращения к API 3x-ui 3.11.0, очередь SQLite, фоновые напоминания и Docker Compose. Проверены код и граничные условия в изолированных тестах. Сетевая пропускная способность пользовательского VPS, защита хостинга и доступность реальной панели под нагрузкой не измерялись.

**Вывод.** Публичные обращения ограничены до вызова бизнес-логики. Число незакрытых регистраций и продлений ограничивается независимо. При длительной активности множества аккаунтов часть обычных пользователей всё ещё может получать задержки и отказы.

## Что обнаружено и изменено

| Наблюдение при проверке первоначальной версии | Поведение итоговой версии |
|---|---|
| Повторная подача одной регистрации вызывала повторное чтение из панели. Разные введённые имена могли занимать отдельные места у администратора | Каждому пользователю доступна одна открытая регистрация. Повтор получает номер существующей заявки. Проверка места выполняется до обращения к 3x-ui. Создание заявки и уведомления происходит в одной транзакции SQLite |
| Для входных действий отсутствовал общий и индивидуальный бюджет. Обычные обращения могли задерживать решения администратора | При настройках по умолчанию пропускается в среднем 12 действий в минуту на пользователя и 60 для обычных аккаунтов в совокупности. Одновременно приняты до трёх пользовательских действий, по одному с аккаунта. Для администратора предусмотрен отдельный допуск. Состояние ограничителя занимает до 4096 записей и освобождается по мере истечения срока |
| Регистрации и сообщения об оплате конкурировали за внимание администратора и место в очереди | По умолчанию доступны 50 мест для регистраций и 100 мест для продлений. Для пользователя доступны одна регистрация и до трёх заявок о платеже. Администратор может отдельно открыть очередь продлений. Закрытие освобождает место, перезапуск сохраняет занятые места |
| Два непривязанных посетителя приводили к двум запросам к панели за один проход напоминаний | Планировщик обходит подтверждённых владельцев. В тесте два непривязанных посетителя дали ноль фоновых запросов к 3x-ui. Незавершённый ввод Email имеет срок 24 часа |
| Telegram может ограничить исходящую доставку | Уведомления сохраняются в SQLite. За проход выполняется до одной попытки отправки на чат. Ответ Telegram с Retry-After откладывает очередную отправку из фоновой очереди. Сбой сети включает повтор с увеличивающимся интервалом |

## Проверенные границы

- На границе индивидуального лимита другой пользователь мог использовать свой запас. На границе общего лимита обработчик обычного пользователя не вызывался. После восстановления запаса запрос снова принимался.
- При занятых публичных местах запрос администратора доходил до обработчика. Ошибка обработчика освобождала занятое место.
- При заполненной очереди регистраций продление принималось. Повтор собственной заявки возвращал тот же номер. Дополнительная регистрация не увеличивала число обращений к API и уведомлений в уже занятой очереди.
- Состояние занятых мест сохранялось при повторном открытии базы. После решения администратора место становилось доступным.
- Compose не публикует входные порты бота. Экземпляр сам обращается к Telegram за обновлениями. [Telegram Bot FAQ](https://core.telegram.org/bots/faq#how-do-i-get-updates)

## Остаточные риски

| Приоритет | Что может произойти | Граница действующей защиты |
|---|---|---|
| Высокий для публичного VPS | Перегрузка канала VPS или открытого адреса 3x-ui нарушит доступность панели и продлений | Лимиты приложения действуют после получения обновлений от Telegram. Состояние внешнего канала и защита провайдера проверяются отдельно |
| Средний | При длительном потоке с разных аккаунтов законный клиент может получить отказ из-за общего бюджета или заполненной очереди | Бюджет сдерживает нагрузку, а отдельные места сохраняют возможность принимать продления при заполненных регистрациях. Публичным пользователям не гарантирована справедливая доля общего бюджета |
| Средний | Задержки Telegram или 3x-ui увеличивают время до решения администратора | Администратор проходит входной ограничитель, но часть операций сериализована общей блокировкой. При недоступной панели заявки сохраняются. Отдельный допуск не гарантирует время ответа |
| Средний при длительной эксплуатации | История решений и уведомлений постепенно занимает диск | Квоты ограничивают открытые заявки. История обработанных записей сохраняется. Контроль свободного места и резервных копий относится к эксплуатации |
| Низкий при штатном развёртывании | Частые перезапуски восстанавливают начальный запас входных действий. Несколько экземпляров получили бы независимые счётчики | Расчёт рассчитан на один процесс long polling. Очереди остаются в SQLite между запусками |

Результат этой проверки подтверждает поведение приложения на границах настроенных лимитов. Число запросов в секунду, которое способен выдержать конкретный сервер, остаётся неизвестным.
